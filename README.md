# 华为分享 1.8 · Windows 端

在 Windows 电脑上，直接和**鸿蒙手机**、**iPad / iPhone** 互传文件。

不需要装助手客户端、不需要登录、不需要云盘中转，走的是局域网直连。
纯 Rust 写成，**一个 exe，双击就能用**，没有 .NET / Visual C++ / Python 之类的运行时依赖。

- 同一个程序同时认两类设备：鸿蒙手机（含鸿蒙 7）和 iPad / iPhone，不用装两份
- 双向：电脑发给设备、设备发给电脑
- 单文件、多文件、整个文件夹（保留目录结构）一次发
- 图形界面（托盘 + 拖放浮窗）和命令行两套入口，功能等价

> 这是一个**第三方互操作性实现**，与华为、苹果公司没有任何隶属或合作关系。

## 三分钟上手

1. 解压整个目录（不要只拖走 exe，`bin\` 要和别的文件放一起）。
2. 双击 **`bin\hwshare.exe`**。它会缩到屏幕右下角的托盘区，同时开始监听——没有安装步骤，没有配置向导。
   - 找不到图标？点托盘左侧的 `^`，它在折叠区里。
3. 把要发的文件**拖到浮窗**上，或者在浮窗里点「选择文件」。

接收方向：让手机 / iPad 打开「华为分享」（iPad 上叫「鸿蒙星河互联」App），
选中本机，电脑右下角会弹出一个自绘的确认框（**否在左、是在右**，30 秒不操作自动拒绝）。

第一次运行 Windows 会问「是否允许访问网络」，**专用和公用两个都要勾**，
否则手机扫不到电脑。用到的端口只有两个：TCP 5684（传文件）、UDP 5684（找设备）。

完整的每一项功能、每个命令行参数、每个环境变量，见 **[`使用说明.md`](使用说明.md)**。

## 现在能做什么（真机实测）

| 方向 | 结果 |
|---|---|
| 电脑 → 鸿蒙手机 | 通，单文件 **14.97 MB/s**（193.8 MB）；301 个文件 8.25 秒 |
| 鸿蒙手机 → 电脑 | 通，**19.80 MB/s**，MD5 一致；4363 个文件 / 900.3 MB 全部落盘 |
| 电脑 → iPad | 通，握手 **6 ms**，小文件端到端 2.6 秒 |
| iPad → 电脑 | 通，16.97 ~ 22.70 MB/s，MD5 一致 |
| 手机 + iPad 同时给电脑发 | 通，两套密码协商互不干扰 |
| 文件夹 / 0 字节文件 / 1.1 GB 单文件 | 通（1.1 GB：80.9 秒，14.6 MB/s） |
| **iPhone** | **没测过**（协议应当与 iPad 相同，但这只是推测） |

实际速度取决于 Wi-Fi 质量；千兆局域网下大致是上面这个量级。

## 两种用法

**图形界面**（日常用这个）

```powershell
.\bin\hwshare.exe
```

托盘常驻，双击托盘图标叫出拖放浮窗。发文件有实时进度浮窗，收到文件在右下角飘一条提示，
提示条左侧的蓝条是倒计时，鼠标停上去会暂停。

**命令行**（批处理、脚本、无人值守）

```powershell
# 扫描附近的设备（手机和 iPad 都能扫到）
.\bin\hwshare-cli.exe discover --seconds 8

# 发文件；只给 IP 的话会自动扫 8 秒找端口
.\bin\hwshare-cli.exe send --to 192.168.1.20:38400 .\photo.png

# 一次发给所有已发现的设备
.\bin\hwshare-cli.exe send --to-all .\photo.png

# 常驻接收，收到的文件都进 D:\接收
.\bin\hwshare-cli.exe serve --dest D:\接收

# 只收一次就退出
.\bin\hwshare-cli.exe listen --dest D:\接收
```

无人值守场景可以设 `HWSHARE_CONFIRM=0`，跳过接收确认框直接收。

## 想改代码

源码在 `src/`，标准 Cargo 工程。

```powershell
.\构建.bat              # 双击也行，等价于 .\src\build.ps1
.\src\build.ps1 -Test   # 单元测试 + 回环测试（应 202 单元 + 6 回环）
```

注意两件事：

- 产物 target 目录**必须放在纯英文路径**下，MinGW 的链接器打不开含中文的目录；
  脚本默认落在 `%LOCALAPPDATA%\HWShareWin\build`，会自动复制回 `bin\`。
- 图标和版本号是 `build.rs` 调 `windres` 编进去的。手敲 `cargo build` 可能跳过这一步，
  出来的 exe 没图标、体积也略有差别，**发版请用 `build.ps1`**。

改协议之前请先读 [`docs/协议与排错.md`](docs/协议与排错.md)，
动代码之前读 [`docs/04-实现要点.md`](docs/04-实现要点.md)——那里记着哪两个常量必须一起改、
改错了会看到什么现象。这两份文档里的每一条都对应过一次真实的翻车。

## 已知限制

- **不支持断点续传**。中断了要重发（已收到的部分不会自动续上，临时文件以 `.part` 结尾）。
- **同一台设备同时只能有一个会话**，并发发送到同一台设备不支持。
- 设备会开多条 file 连接，当前只用第一条；单连接已能跑满，极限吞吐还有空间。
- **iPhone 从未实测**。
- 只支持 Windows 10 / 11（x64）。没有 32 位、没有 ARM 版、没有 Linux 版。
- 公司网络、访客 Wi-Fi 常开「AP 隔离」，设备之间互相看不见，这种网络下用不了。

## 已验证 / 未验证

**已验证（真机，2026-11）**

- 电脑 → 鸿蒙手机：301 个文件 8.25 秒；193.8 MB 单文件 14.97 MB/s；1.1 GB 单文件
- 鸿蒙手机 → 电脑：302 个文件、4363 个文件 / 900.3 MB、193.8 MB 单文件 19.80 MB/s，MD5 全部一致
- iPad → 电脑：299.6 MB 16.97 ~ 22.70 MB/s（MD5 一致）；iPad 主动发也能收
- 电脑 → iPad：握手 6 ms，端到端 2.6 秒，多种尺寸 MD5 一致
- 文件夹（含子目录）、0 字节文件、中文 / emoji / 203 字节超长文件名
- 手机与 iPad 同时发送
- 自动化测试：**202 个单元测试 + 6 个回环测试**（回环走真实 TCP，不需要设备），release 零警告

**未验证**

- iPhone（一次都没试过）
- 其他鸿蒙版本、其他机型
- 传输中途在 Apple 端取消的表现
- 长时间大文件稳定性（1.1 GB 跑通，但没做几小时的压测）
